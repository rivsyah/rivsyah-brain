**Backend (2026-07-12):** Laravel 13 murni (tanpa Filament, pola sama dengan backend dpld) di `C:\Users\rivsy\Herd\sipama-app` → http://sipama-app.test, SQLite, timezone Asia/Jakarta. Frontend desain di-serve sebagai `resources/views/app.blade.php` (@verbatim), aset + layar JSX di `public/` (path aset jadi absolut `/assets/`), `data.js` diganti `public/app/store.js` API-backed (fetch + CSRF + session auth + toast). API di routes/web.php prefix `/api`, controller tunggal `ApiController`: login/logout/me, bootstrap & poll (payload persis bentuk `window.SIPAMA_DATA`; kolom di-remap: idx→index, description→desc, next_due→next, in_time→in, code→id, ticket→id), POST incidents (triase otomatis dari matriks severity → status+SLA, tiket INC-YYYY-MM-XXXX), POST incidents/{ticket} (selesai/eskalasi), POST visitors (pra-registrasi VIS-XXXX), POST crisis (Mode Krisis tersimpan di tabel settings, sinkron lintas user via polling 5 detik). Layar yang di-wire ke API: AppShell (logout + jam live), IncidentsScreen (form controlled + aksi), AccessScreen (pra-registrasi), EmergencyScreen (krisis dari server). Login: admin@ / kasubbag@ / komandan@ / operator@kemlu.go.id, password `password`. Test: tests/Feature/SipamaApiTest.php + SipamaFeatureTest.php (26 test total, semua lulus).

**Tiga jebakan penting dari impor v2:** (1) **Cache peramban** menyajikan modul lama sehingga halaman kosong — diatasi dengan penanda versi `?v={{ $v }}` (filemtime maks di public/app + _ds_bundle.js) pada setiap tag skrip; blok `<script src>` dikeluarkan dari `@verbatim` agar Blade bisa menyisipkannya. (2) **CSRF basi setelah ganti peran** — `login()` memicu `session()->regenerate()`, token lama tolak semua POST (419); diatasi: `login()` mengembalikan `csrf_token()` baru dan store.js menyimpan CSRF sebagai `let` + `setCsrf()`. (3) Layar v2 dari Claude Design adalah **tampilan saja** (hanya memanggil toast/login) — seluruh RBAC, panel myTasks, modul pengadaan, dan tombol rekam harus disambungkan ulang setelah impor; memasang layar v2 menimpa berkas layar lama.

**RBAC + proses bisnis berjenjang (2026-09-05):** 4 jabatan berlevel di `users.role_key`/`users.level` — Kepala KPA (4), Kepala PamRumga (3), Kepala Sub Bagian Pengamanan (2), Operator (1). `User::PERMS` = 25 izin (izin => level minimum), `User::EXCLUSIVE` = `pengadaan.setujui` hanya level 4 (pemisahan tugas: PamRumga TIDAK boleh setujui anggaran meski level lebih tinggi), `hasPerm()`/`permList()`; gerbang `ApiController::authorizeAct()` di tiap endpoint aksi → 403. Empat alur berjenjang: (1) insiden Kritis ditutup pengguna level<3 → status "Menunggu Verifikasi" → aksi `verifikasi` oleh PamRumga; (2) CAPA Verifikasi→Selesai butuh `capa.verifikasi`; (3) rantai pengadaan tabel `procurements` (PRC-YYYY-XXXX): Kasubbag ajukan → PamRumga rekomendasi/tolak → KPA setujui, aset jadi maint "Dalam Pengadaan"; (4) Mode Krisis: aktifkan level 2+, nonaktifkan level 3+. Payload tambah `session.roleKey/level/perms`, `procurements`, `myTasks`, `sopCompliance[].id`, `perwakilan[].id`. **myTasks pakai rentang supervisi**: tugas punya tingkat pemilik, pengguna hanya melihat tingkatnya sendiri + 1 di bawah (tanpa ini panel KPA tenggelam pekerjaan pelaksana karena mewarisi semua izin); insiden ber-assignee nama pengguna selalu muncul sebagai antrean pribadi. Frontend: `window.SIPAMA_CAN(perm)` di store.js, gating tombol di semua layar. 8 endpoint rekam yang sebelumnya hilang ditambahkan: personnel, findings, threats, drills, contacts, perwakilan(+update), sop. Dokumentasi lengkap: `docs/proses-bisnis.md`. Test: 40 hijau/268 assertion (SipamaApiTest 7 + SipamaFeatureTest 16 + SipamaRoleTest 14). Skrip verifikasi matriks peran via curl ada di scratchpad sesi (`verify-roles.sh`, 14 cek).
